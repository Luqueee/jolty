# Controlled large-model fallback

The controlled task runner can optionally escalate a Laya decision before execution. The default CLI remains Laya-only. `pnpm run jolty -- run cookie-overlay --fallback --trace` enables the ChatGPT-signed-in Codex adapter for that run. `codex login status` must report a ChatGPT login; the fallback does not use an API key. Set `JOLTY_FALLBACK_THRESHOLD` to a number from 0 to 1 to change the experimental threshold (default `0.2`).

Escalation has two explicit reasons: `low_confidence` when Laya returns a finite confidence below the threshold, and `model_failure` when Laya fails and the policy enables that reason. A confidence equal to the threshold stays on the fast path. The threshold is a fixture-study setting, not a calibrated probability of correctness. The current implementation does not retry after an executed wrong action; validation failure remains visible and stops the task. A fallback decision is selected from the same retrieved candidates and target-free actions as Laya. It receives the goal, compact page URL and title, and candidate descriptions, with no raw HTML, screenshot, or form values. The selected action goes through the same deterministic binding, executor, and validator.

Each step trace keeps the final `decision` and, when escalation occurs, the original `fast_decision`, `fallback_reason`, fallback provider/model, fallback decision, fallback latency, input/output tokens, and final validation outcome. `timing.decision_latency_ms` remains Laya-only; `timing.fallback_ms` and `timing.total_decision_ms` show the added time. Unknown provider error text is removed. Subscription usage has no per-test API price, so estimated USD cost is `null`.

Run `pnpm run benchmark:hybrid` for one warmup and five measured serial runs per task and mode, or set `JOLTY_BENCH_RUNS`. The benchmark compares Laya-only and hybrid on the same fresh local fixtures and exact success texts. It reports fast-path coverage, fallback rate, task success, task and decision latency, Codex calls, tokens, and failure reasons. Browser/model startup and page creation are outside measured task duration; each Codex CLI startup is included in fallback latency. These controlled fixtures do not establish a safe threshold or general-site recovery.
