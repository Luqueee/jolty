# Large-model decision baseline contract

Milestone 10 compares a large-model browser decision baseline with the heuristic and Laya on the same controlled tasks. `packages/decision/benchmarks/llm-baseline.ts` provides the per-step contract. It does not issue network requests by itself or execute browser actions.

`evaluateLargeModelDecision(input, adapter, prices?)` receives the existing `DecisionInput` with a goal, compact `BrowserState`, and retrieved Top-K candidates. It sends a constrained `ModelQuestion` to the injected adapter. The question contains goal, page URL without query or fragment, title, and candidate options keyed by ID. It omits raw HTML, screenshots, the full element list, and form values. Candidate names and the goal are still page or user data: review them before connecting a remote provider, and use only controlled fixture data for this baseline.

The adapter returns one option key and optional input/output token counts. The harness validates the option against the offered choices, then returns the action and target ID as data. An unknown key or malformed usage is an `invalid_output` failure. A thrown adapter error is a `provider_error` failure; the provider's error text is omitted from the result. Neither result executes an action. A caller must use the existing executor and validator to measure task success.

Every attempted decision reports one model call and elapsed decision time. Token counts are `null` if the adapter cannot report them. Estimated USD cost is `null` unless the caller supplies both nonnegative per-million-token prices and the adapter reports valid token counts. The price must match the chosen provider and model at benchmark time; no price is hardcoded.

The subscription adapter runs `codex exec` with the existing ChatGPT login, `gpt-6-sol`, read-only sandboxing, an ephemeral session, and an output schema whose choice enum contains only the offered keys. Run `codex login status` to check the login, then `JOLTY_INCLUDE_CODEX=1 JOLTY_BENCH_RUNS=1 pnpm run benchmark:compare` for one warmup and one measured run per task and policy. Increase `JOLTY_BENCH_RUNS` for more stable estimates. The Codex CLI starts a new agent turn per decision, so its startup and prompt overhead are included in decision and task latency. This is a subscription-backed agent baseline, not a direct model API latency comparison.

The comparison runner executes each choice through the same controlled task executor and validator used for the heuristic and Laya. The adapter exposes token usage when Codex reports it. Estimated USD cost stays `null` because ChatGPT subscription usage is not separately billed as API requests. There are no automatic retries. The command does not use an API key. The [OpenAI billing guidance](https://help.openai.com/en/articles/9039756-managing-billing-for-chatgpt-and-the-api-platform) explains that API billing is separate, and the [Codex plan guidance](https://help.openai.com/en/articles/20001275/) describes ChatGPT sign-in usage.
