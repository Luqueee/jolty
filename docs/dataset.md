# Controlled trace dataset v1

Run `pnpm run dataset:export` to collect one fresh run of each of the five controlled tasks. The default output is `artifacts/dataset-v1/`; this directory is ignored by Git. An optional positional path changes the output directory. `pnpm run dataset:export --fallback` enables the existing Codex fallback, which uses the signed-in ChatGPT subscription and the experimental 0.2 confidence threshold. The default export uses Laya only. Export is a separate offline pass and adds no work to the browser decision hot path.

The exporter writes `traces.parquet` and `manifest.json`. The Parquet file has one row per attempted decision and schema version `1`. Scalar columns are `schema_version`, `sample_id`, `fixture_id`, `split_group`, `split`, `goal`, `fast_confidence`, `fallback_reason`, `validation_outcome`, `final_outcome`, `label_status`, and `label_source`. Structured columns are JSON strings: `fast_model`, `browser_state`, `candidates`, `fast_decision`, `teacher_decision`, `teacher_model`, `executed_decision`, `training_action`, and `proposed_action`. A missing optional value is an empty string in Parquet; a present structured value is JSON encoded. `browser_state` contains only fixture origin/path, title, and projected interactive elements. Each candidate records its ID, retrieval score, and score signals.

`training_action` is populated only when the executed action and target match the fixture's step label **and** the deterministic step validation passed. `label_source` then equals `fixture_action_and_deterministic_outcome`. A teacher or fallback choice is stored separately and never becomes a training label on its own. A failed or mismatched step remains in the dataset with `label_status=unvalidated` and an empty training action. This avoids treating a coincidental passing page state as proof that the selected action was correct.

The exporter accepts only exact URLs for the five local fixtures. It projects fields through an allowlist, omits form values, URL query/fragment, raw errors, and validation messages, and rejects common email/credential/token patterns in exported text. This is a controlled fixture collector; do not use it to export arbitrary websites or user supplied fixture content without a separate privacy review. The output is a training artifact, not an operational trace store.

The split is fixed by fixture: `modal`, `cookie-overlay`, and `ambiguous-row` are train; `settings` is validation; `dynamic-results` is test. All steps and repeated runs of one fixture must stay in its assigned split. Dataset integrity checks reject duplicate sample IDs, invalid candidates/scores/decision targets, inconsistent label provenance, and split mismatches. The exporter reads back every Parquet column before publishing the file. The manifest records schema version, row and validated-label counts, split assignments, and a SHA-256 digest of canonically ordered rows. Reproduce a dataset using the same repository commit, pinned dependencies, model revision recorded in each row, fixture content, and fallback setting; compare the content digest. Model behavior and timing can still vary between runs.

These five authored templates are a smoke dataset, not evidence of cross-site generalization or a representative training corpus. The held-out fixtures provide separation within this small set; they do not establish independence across real sites or page families. Expansion should group all pages sharing a site or template family before assigning splits.

Use `pnpm run research:readiness` to audit an export before model adaptation. The reader verifies the schema, row count, and manifest content digest; the [research readiness report](research-readiness.md) describes the current admission gates and limitations.

The separate [public-site research corpus pilot](research-corpus.md) uses curated browser cases and a JSON v0 artifact. Its collection and validation rules differ from this controlled Parquet v1 exporter. The JSON pilot is not a drop-in v1 dataset.
