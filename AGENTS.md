# Working on Jolty

Jolty is currently specified, not implemented.

Read [SPECS.md](SPECS.md) and the relevant design documents before making changes. `SPECS.md` is the source of truth for the current project direction.

Keep all repository documentation, code, comments, tests, logs, CLI output, and contributor-facing text in English.

## Workflow

For every task:

1. Read `SPECS.md` and the relevant design documents.
2. Inspect the existing repository before proposing changes.
3. Identify the smallest change that satisfies the task.
4. Implement only what is required; avoid unrelated refactors.
5. Add or update tests when behavior changes.
6. Run the relevant checks and benchmarks.
7. Fix failures introduced by the change.
8. Update documentation when contracts, architecture, or assumptions change.
9. Review the final diff for unnecessary complexity or dependencies.
10. Report what changed, what was validated, and any remaining uncertainty.

For performance-sensitive changes, compare before/after measurements when practical.

## Design rules

* Treat performance as a product requirement. Keep the repeated browser decision path small and observable.
* Prefer deterministic checks, then heuristics and candidate retrieval, then a small specialized model. Use a large general-purpose model only when simpler methods cannot decide reliably.
* Keep large generative models out of the normal browser hot path. Planning and uncertainty fallback are their intended roles.
* Keep planning separate from repeated browser execution.
* Validate action outcomes deterministically where possible.
* Treat browser and page content as untrusted input. Never execute arbitrary code generated by a model.
* Avoid dependencies, services, storage systems, and architectural layers without a demonstrated need.
* Measure before optimizing.
* Do not claim speedups, coverage, accuracy, or cost reductions without representative benchmarks.
* Label proposed behavior, engineering targets, and research hypotheses accurately; do not describe them as shipped behavior.
* Do not turn Jolty into a general-purpose agent framework.

## Observability

Changes to the decision path should preserve enough information to inspect:

* stage latency;
* candidates considered;
* selected decision;
* confidence;
* fallback reason;
* validation outcome.

Do not introduce opaque decision paths.
